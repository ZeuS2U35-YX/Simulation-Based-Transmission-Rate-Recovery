# Software and computing environment

This file separates the environment recorded for the original analyses from the environment used for later lightweight validation. The repository does not include an `renv.lock` file, Python requirements file, or container definition. It therefore supports reproducible workflows and retained-result validation, but it does not claim exact restoration of every historical package version.

## Original HPC configuration

The Slurm scripts for Experiments 2-4 explicitly load:

- `StdEnv/2020`;
- R `4.1.2`;
- the user library path `$HOME/packages-R4.1`.

These settings identify the intended HPC R module. They do not determine the exact historical version of every installed package, and the complete HPC runs did not record an exact `pomp` version.

Experiment 3 also includes a session record for a later single-run diagnostic reconstruction. That reconstruction used:

- R `4.5.2` on Apple silicon macOS;
- `pomp` `6.4`;
- `deSolve` `1.42`;
- `coda` `0.19-4.1`;
- `mvtnorm` `1.3-7`;
- `data.table` `1.18.2.1`;
- `digest` `0.6.39`;
- `lattice` `0.22-7`.

These versions describe the post hoc diagnostic reconstruction, not the original 200-task HPC environment.

## Currently tested lightweight environment

The current repository validation parsed the R sources and regenerated the documented compact-result figures with R `4.5.2`. Packages used by the current workflows include:

- `pomp` `6.4`;
- `tidyverse` `2.0.0`;
- `ggplot2` `4.0.3`;
- `digest` `0.6.39`;
- `ragg` `1.5.2`.

`svglite` is optional. When it is unavailable, the selected-task figure scripts use R's native SVG device. These are tested versions, not verified minimum requirements and not evidence of the complete historical HPC package set.

## R dependencies

The principal R dependencies are:

- `pomp` for POMP construction, simulation, iterated filtering, particle filtering, filtering summaries, and Monte Carlo likelihood aggregation;
- `tidyverse`, including `ggplot2`, for the developmental Experiment 1 workflow and data visualization;
- `digest` for checksum and provenance validation in the selected-task figure workflows;
- `ragg` for high-resolution PNG and TIFF export when available;
- `svglite` for editable SVG export when available;
- base R packages including `stats`, `graphics`, `grDevices`, `utils`, and `tools`.

A practical installation for the current workflows is:

```r
install.packages(c("pomp", "tidyverse", "digest", "ragg", "svglite"))
```

The C snippets embedded in the POMP models require a compiler toolchain compatible with the installed R distribution.

## Optional Python figure utility

`experiments/experiment_4_nmif600_model_comparison/regenerate_exp4_figures.py` is an optional, non-canonical figure generator. The authoritative Experiment 4 comparison, selected-task, and convergence figures are generated by the documented R scripts.

The Python utility imports NumPy, pandas, and Matplotlib. It was syntax-checked and tested in an available Anaconda environment with:

- Python `3.11.7`;
- NumPy `1.26.4`;
- pandas `2.1.4`;
- Matplotlib `3.8.0`.

These are tested versions rather than historical or minimum requirements. One possible installation command is:

```bash
python -m pip install numpy pandas matplotlib
```

## Command-line and HPC tools

- `Rscript` for local and batch execution;
- Bash for workflow wrappers;
- Slurm commands such as `sbatch`, `squeue`, and `sacct` for full HPC workflows;
- an environment-modules implementation for the recorded `module load` commands;
- Git for version control.

The lightweight figure and summary commands do not require Slurm. Full simulation, MIF2, and particle-filter workflows are computationally expensive, so consult the relevant experiment README before running them.
