# Software and computing environment

This file distinguishes recorded analysis configuration from software that was only tested during repository validation. The repository does not currently include `renv.lock`, a Python requirements file, or a container definition, so it does not claim exact environment restoration.

## Recorded analysis configuration

The Slurm scripts for Experiments 2–4 explicitly load:

- `StdEnv/2020`;
- R `4.1.2`;
- the user library path `$HOME/packages-R4.1`.

This verifies the intended HPC R module, but it does not establish the exact historical version of every installed R package. No exact historical `pomp` version was recorded for the complete HPC runs.

Experiment 3 also contains a session record for its later, single-run diagnostic reconstruction. That reconstruction used:

- R `4.5.2` on Apple silicon macOS;
- `pomp` `6.4`;
- `deSolve` `1.42`;
- `coda` `0.19-4.1`;
- `mvtnorm` `1.3-7`;
- `data.table` `1.18.2.1`;
- `digest` `0.6.39`;
- `lattice` `0.22-7`.

These versions document the post hoc diagnostic reconstruction, not the original 200-task HPC environment.

## Environment used for lightweight validation

The current repository validation successfully parsed all R scripts and regenerated the documented compact-result figures with:

- R `4.5.2`;
- `pomp` `6.4`;
- `tidyverse` `2.0.0`.

These are currently tested versions. They should not be interpreted as verified minimum versions or as proof of the historical HPC package set.

## R dependencies

The principal analysis dependencies are:

- `pomp` for POMP construction, particle filtering, MIF2, filtering summaries, and Monte Carlo likelihood aggregation;
- `tidyverse` for the developmental Experiment 1 scripts;
- base R packages such as `stats`, `graphics`, `grDevices`, `utils`, and `tools`.

A basic current installation can be prepared with:

```r
install.packages(c("pomp", "tidyverse"))
```

Compiling the embedded C snippets used by `pomp` requires a working compiler toolchain compatible with the installed R distribution.

## Python utility

`experiments/experiment_4_nmif600_model_comparison/regenerate_exp4_figures.py` is an optional alternative figure generator. It is not the canonical Experiment 4 workflow; the canonical comparison and convergence PDFs are generated by the two documented R scripts.

The optional Python utility imports:

- NumPy;
- pandas;
- Matplotlib.

It was syntax-checked and its imports were tested in an available Anaconda environment with Python `3.11.7`, NumPy `1.26.4`, pandas `2.1.4`, and Matplotlib `3.8.0`. These are currently tested versions, not historical or minimum requirements.

One possible installation command is:

```bash
python -m pip install numpy pandas matplotlib
```

## Command-line and HPC tools

- `Rscript` for local and batch execution;
- Bash for workflow wrappers;
- Slurm commands such as `sbatch` and `squeue` for the full HPC workflows;
- an environment-modules implementation for the recorded `module load` commands;
- Git for version control.

The lightweight figure commands do not require Slurm. Full simulation, MIF2, and particle-filter workflows are computationally expensive; consult the experiment-specific README before running them.
